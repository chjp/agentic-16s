一条 read 的旅程A read's journey

16S 扩增子流程每一步在做什么、对数据有什么假设，以及面对来自不同实验室、不同测序仪的几十个研究时，这些假设是怎样一个个被打破的。nf-core/ampliseq 就是把 DADA2 这些工具包装成一条流程。所有例子都来自本项目已经跑过的 8 个 IBD 研究。

What each step of the 16S amplicon pipeline does, what it assumes about the data, and how those assumptions broke one by one when dozens of studies from different labs and sequencers came in. nf-core/ampliseq is DADA2 and friends wrapped into one workflow. Every example comes from the eight IBD studies this project has already processed.

1 · DADA2核心是 DADA2：把每条 read 截成同样长度，再用统计检验区分“真实的序列变体（ASV）”和“测序错误”。The core is DADA2: it cuts every read to the same length, then uses a statistical test to tell real sequence variants (ASVs) from sequencing errors.
2 · 假设assumptions这个检验需要几个前提：质量分数是真的、reads 一样长、引物和方向已知、同一批测序。公共数据库里的研究经常不满足。The test needs a few things to be true: real quality scores, equal read lengths, known primers and orientation, one sequencing batch. Public studies often break them.
3 · 跨研究across studies不同研究测的是基因的不同片段，ASV 一个也对不上，最后只能退回到属水平比较。Studies sequence different parts of the gene, so not one ASV matches between them, and the comparison falls back to genus level.

为什么两个 V3–V4 研究连一个 ASV 都对不上Why two V3–V4 studies do not share a single ASV

ASV 是精确的字符串，差一个字母就是另一个 ASV。35756051 用 785R，37661264 用 806R，两个反向引物在基因上差 2 个碱基。切掉引物以后，同一个细菌的序列一个以 …GCAAACA 结尾，另一个以 …GCAAACAGG 结尾。

An ASV is an exact string; one letter more and it is a different ASV. 35756051 used 785R and 37661264 used 806R, and the two reverse primers sit 2 bases apart on the gene. After primer removal, the same bacterium's sequence ends in …GCAAACA in one study and …GCAAACAGG in the other.

这就是 ml-results.md 里“任意两个研究之间 0 个共享 ASV”的原因之一，跨研究模型只好用属。This is one reason ml-results.md found zero ASVs shared between any two studies, so the cross-study model uses genera.

FASTQ · 质量分数FASTQ · quality scores

每个碱基都带着一句“我有多可信”Every base comes with a note on how far to trust it

FASTQ 的每条 read 有四行：名字、序列、加号、质量。质量分数 Q = −10·log10(p)，p 是这个碱基读错的概率：Q30 表示千分之一，Q20 表示百分之一。DADA2 用它们做两件事：算每条 read 的“预期错误数” EE（第 3 节），以及学错误模型（第 4 节）。

Each FASTQ read has four lines: name, sequence, a plus sign, and quality. A quality score is Q = −10·log10(p), where p is the chance that the base is wrong: Q30 means one in a thousand, Q20 one in a hundred. DADA2 uses them twice: to compute each read's expected errors EE (section 3), and to learn the error model (section 4).

每根柱子是一个碱基的 Q 值（悬停看数值）。Each bar is one base's Q value (hover for numbers).

错误模型要在这些点之间画一条“质量分数 → 错误率”的曲线。The error model has to draw a "quality score → error rate" curve through these points.

filterAndTrim · mergePairsfilterAndTrim · mergePairs

截断实验室：悬崖在哪里Truncation lab: where the cliff is

DADA2 要求所有 reads 一样长，所以先把 R1 截到 truncF、R2 截到 truncR。比截断长度短的 read 整条丢掉，这是悬崖。截完后再算 EE = Σ10−Q/10，超过 maxEE 的也丢掉；尾巴质量差，截得越长 EE 越大，这是斜坡。最后 R1 和 R2 要在中间重叠至少 12 nt 才能拼起来。每个点是一个 run（模拟数据）。

DADA2 needs every read to be the same length, so R1 is cut to truncF and R2 to truncR. A read shorter than the cut is dropped whole: that is a cliff. Then EE = Σ10−Q/10 is computed and reads above maxEE are dropped too; the tail is poor, so the longer the cut, the larger the EE: that is a slope. Finally R1 and R2 must overlap by at least 12 nt to merge. Each dot is one run (simulated data).

learnErrors · dadalearnErrors · dada

DADA2 的核心：这是新序列，还是测序错误？The core of DADA2: a new variant, or a sequencing error?

下面真的在浏览器里跑 DADA2 的核心算法（简化版：60 nt、只有替换错误）。我们放进 5 个真实序列（A 40,000 条，B 8,000，C 600，D 60，E 80；C 和 E 与 A 只差 1 个碱基），模拟测序错误后得到几千种不同的序列。DADA2 从最多的序列开始，一个个问：如果它只是某个更多的序列的测序错误，预计会出现 μ 条；实际有 a 条。a 远大于 μ 吗？

This runs the core of the DADA2 algorithm in your browser (simplified: 60 nt, substitution errors only). We put in five real sequences (A 40,000 reads, B 8,000, C 600, D 60, E 80; C and E differ from A by one base), simulate sequencing errors, and get a few thousand distinct sequences. DADA2 starts from the most abundant one and asks of each in turn: if this were only a sequencing error of a more abundant sequence, we would expect μ copies; we see a. Is a far above μ?

λ = Πpos (相同match ? 1−epos : epos/3)  ·  μ = ncenter · λ  ·  p = P(X ≥ a | X ≥ 1), X ~ Poisson(μ)  ·  p < ΩA → 新 ASVp < ΩA → new ASV

真实的 DADA2 按碱基替换类型 × 质量分数学错误率，每个测序批次单独学（我们的 samplesheet 从 read 名字里的 flowcell 读出批次，填进 run 列）。默认 pool = FALSE 每个样本单独推断；pooled 把所有样本合起来，能找到更稀有的变体，但 37661264 每个方向要 1 小时 45 分钟（E11），所以我们改用 pseudo。

Real DADA2 learns error rates per substitution type × quality score, separately for each sequencing batch (our samplesheet reads the flowcell from the read names into the run column). By default each sample is inferred on its own; pooled combines all samples and finds rarer variants, but took 1 h 45 min per read direction for 37661264 (E11), so we use pseudo.

removeBimeraDenovo · assignTaxonomyremoveBimeraDenovo · assignTaxonomy

嵌合体，和给序列起名字Chimeras, and putting a name on a sequence

PCR 换模板造出的“拼接怪”A hybrid made by PCR switching templates

PCR 时聚合酶可能复制到一半掉下来，下一轮接到另一个细菌的模板上继续，得到“前半段 A + 后半段 B”的序列。removeBimeraDenovo 检查每个 ASV：能不能由两个更多的 ASV 左右拼出来？能就删掉。

During PCR the polymerase can fall off halfway and, in the next cycle, continue on another bacterium's template, giving a sequence that is "first half A, second half B". removeBimeraDenovo checks each ASV: can it be built from the left of one more abundant ASV and the right of another? If so, it goes.

朴素贝叶斯：k-mer 投票Naive Bayes: k-mers vote

assignTaxonomy（RDP 方法）把序列拆成所有 8 个碱基长的小段（8-mer），看它们更像哪个属。为了给出置信度，它重复 100 次：每次随机抽 1/8 的 8-mer 重新投票。100 次里至少 50 次投给同一个属（minBoot 50），才写上属名，否则只写到科。

assignTaxonomy (the RDP method) breaks a sequence into every 8-base word (8-mer) and asks which genus they look like. To get a confidence it repeats this 100 times, each time voting with a random 1/8 of the words. Only when at least 50 of the 100 votes agree (minBoot 50) does it write the genus; otherwise it stops at family.

简化版：只有两个属，没有测序错误。真实的分类器同时比较几千个属。之后 addSpecies 用完全匹配补到种，它在 37661264 上每块要 15–17 GB 内存、总共约 5 小时（E14），所以新研究跳过这一步。Simplified: only two genera and no sequencing errors; the real classifier compares thousands of genera at once. After this, addSpecies adds species by exact matching. On 37661264 it needed 15–17 GB per chunk and about 5 hours in all (E14), so new studies skip it.

同一份粪便，三种方案，三个答案One stool sample, three protocols, three answers

每种方案（引物、区域、DNA 提取、平台）对每个细菌的“放大倍数”不同（McLaren 等 2019）。看相对丰度，三种方案对同一个样本给出不同的组成。看 CLR（对数比），方案的影响变成每个属一个固定的偏移：同一研究里健康和 IBD 之间的差别不变。示意数据。

Each protocol (primers, region, DNA extraction, platform) amplifies each bacterium by its own factor (McLaren et al. 2019). In relative abundance, three protocols give three different pictures of the same sample. In CLR (log-ratios), the protocol becomes one fixed offset per genus: the difference between healthy and IBD inside a study stays the same. Illustrative numbers.

固定阈值会失败，研究内的排序不会，除非偏移和标签重合A fixed threshold fails; ranking within a study does not, unless the offset lines up with the label

这个领域怎么应对异质性How the field copes with heterogeneity

五种常见做法，各自修好了什么、漏掉了什么Five common approaches: what each fixes and what it misses

另一条路 · Chen, Marsh & Al-Hebshi 2022（SMDI）Another route · Chen, Marsh & Al-Hebshi 2022 (SMDI)

不先找精确序列，直接问每条 read：你像哪个已知物种？Skip the exact sequences and ask each read: which known species do you look like?

DADA2 先回答“样本里到底有哪些精确序列”（ASV），再给它们起名字。SMDI 论文（牙周炎的龈下微生物失调指数，J Dent Res 2022）走的是另一条路：先严格过滤，再把每一条 read 直接用 BLASTn 和整理好的 16S 参考库比对，记成最像的那个物种。这样不同研究、不同区域的数据最后都落在同一套物种名上，可以直接合并。论文用这条路合并了 6 个已发表的研究（覆盖 V1–V2、V1–V3、V3–V5、V4 等区域，也有 454 数据），3 个用来训练，3 个用来验证。

DADA2 first answers "which exact sequences are in the sample" (ASVs) and names them afterwards. The SMDI paper (a subgingival microbial dysbiosis index for periodontitis, J Dent Res 2022) takes another route: filter hard, then compare every read directly with curated 16S references using BLASTn, and record it as the species it matches best. Data from different studies and regions then end up on one set of species names and can be pooled directly. The paper pooled six published studies this way (V1–V2, V1–V3, V3–V5, V4 and more, including 454 data): three for training, three for validation.

从物种计数到一个数字：SMDIFrom species counts to one number: the SMDI

物种计数先做 CLR（零值用最小相对丰度的一半补）。在训练集上用随机森林（1,000 棵树）找出最能区分牙周炎和健康的物种，按重要性（Gini）阈值挑出 49 个：31 个和牙周炎相关（T. denticola、M. timidum、Fretibacterium、T. forsythia 等），18 个和健康相关（A. naeslundii、S. sanguinis 等）。指数就是一个差：

Species counts are CLR-transformed first (zeros get half the smallest relative abundance). A random forest (1,000 trees) on the training set finds the species that best separate periodontitis from health, and an importance (Gini) cutoff keeps 49: 31 linked to periodontitis (T. denticola, M. timidum, Fretibacterium, T. forsythia and others) and 18 linked to health (A. naeslundii, S. sanguinis and others). The index is one difference:

SMDI = mean CLR(牙周炎相关物种periodontitis-linked species) − mean CLR(健康相关物种health-linked species)

论文的结果：训练集 AUC 0.96，另外 3 个研究上 0.92；指数大约从 −6 到 5，0 附近分开大多数样本。只用 3 个属（Fretibacterium、Treponema、Actinomyces）的简化版 AUC 也有 0.93。同一批样本测两个区域时指数高度相关（V1–V3 对 V3–V5：r = 0.89；V1–V2 对 V4：r = 0.95），但 V4 让指数整体左移约 1 个单位，正是“跨研究”一节里方案带来的固定偏移。作者自己也写道，把指数用到新数据上需要统一生物信息学流程。

The paper's results: AUC 0.96 on the training set and 0.92 on three other studies; the index runs from about −6 to 5, and values near 0 separate most samples. A simplified version with only three genera (Fretibacterium, Treponema, Actinomyces) still reaches AUC 0.93. The same samples sequenced in two regions gave highly correlated indexes (V1–V3 vs V3–V5: r = 0.89; V1–V2 vs V4: r = 0.95), but V4 shifted the index left by about one unit, which is the fixed protocol offset of the cross-study section. The authors themselves note that using the index on new data needs a standardized bioinformatic workflow.

放到我们的问题清单上Against our list of problems

影响变小Matter less

  • 没有固定截断长度，只有最短长度：不会出现 E23 那种“差 1 bp 整批丢光”（Q05、Q07）No fixed cut length, only a minimum: no E23-style "1 bp short, whole batch gone" (Q05, Q07)
  • BLASTn 默认两条链都搜，read 方向不再是硬要求（Q08）BLASTn searches both strands by default, so read orientation is no longer a hard requirement (Q08)
  • 不同区域、不同平台落到同一套物种名上，不再有“0 个共享 ASV”Different regions and platforms land on the same species names: no more "zero shared ASVs"

仍然会遇到Still there

  • 滑窗 Q35 过滤要真实的质量分数（Q01）；它的质量过滤也查引物错配，所以还得知道引物（Q13、Q14）The Q35 window filter needs real quality scores (Q01); the filter also checks primer mismatches, so the primers must still be known (Q13, Q14)
  • 下载层（Q02–Q04）和策展层（Q16–Q22）的问题与分析方法无关Archive problems (Q02–Q04) and curation problems (Q16–Q22) do not depend on the analysis method
  • 长度阈值、Q35 还是 Q30，每个数据集要有人定The length cutoff, and Q35 vs Q30, are set per dataset by a person

新的代价New costs

  • 98% 也是悬崖：120 nt 里 3 个错误就只剩 97.5%，read 找不到匹配（上面的演示可以试）98 % is a cliff too: 3 errors in 120 nt leave 97.5 %, and the read finds no match (try it in the demo)
  • 离不开整理好的参考库：口腔有 HOMD，肠道没有同样细到物种的库，V4 也很少能分开肠道的物种It depends on a curated reference: the mouth has HOMD, the gut has nothing as fine-grained, and V4 rarely separates gut species
  • 每条 read 都要比对一次，计算量随 reads 数增长；方案偏差还在（V4 平移约 1 个单位）Every read is aligned once, so the work grows with the read count; protocol bias remains (V4 shifted about one unit)

    留给你想的问题Questions to think about

    在重新设计之前Before redesigning anything

    • 每一步对数据做了什么假设？谁来检查这个假设在这个研究里成立？What does each step assume about the data, and who checks that the assumption holds for this study?
    • 哪些参数是“悬崖”（差 1 bp 全丢），哪些是“斜坡”（差一点丢一点）？能不能把悬崖都换成斜坡？Which parameters are cliffs (1 bp short, all lost) and which are slopes (a little off, a little lost)? Can every cliff become a slope?
