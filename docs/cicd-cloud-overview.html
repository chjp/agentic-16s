1全局架构

实线是已有或正在做的数据流，蓝色虚线是计划中的。字母对应图下的说明。

  • AMac 上传固定的代码快照和输入清单（manifest、runs.csv）到 GCS。快照固定以后，后来的修改不会混进正在跑的 job（E13 的教训）。
  • BBatch VM 从 GCS 读快照和输入，跑完把 tables、报告、日志写回 GCS。它只能新建对象，不能覆盖或删除。
  • CMac 下载结果，合并进 studies/<PMID>/，然后和参考结果比对（compare_tables.py），或者入库。
  • Dreads 从 ENA / NCBI 直接下到 VM，FASTQ 在完整性检查通过后就地删除，不回传。
  • E（计划）Mac 和 GitHub 之间 git push / pull。每个 PR 自动跑 CI。
  • F（计划）打 tag 后由 CI 发布代码快照。快照的内容 hash 和 git sha 记在一起，每个结果都能查到是哪个版本算出来的。
